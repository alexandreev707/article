# Render — бесплатный план: инструкция для администраторов

Резюме по развёртыванию и эксплуатации **только на free tier** Render.

---

## Что можно бесплатно

| Ресурс | Free |
|--------|------|
| **Web Service** (Docker) | Да, с ограничениями (см. ниже) |
| **PostgreSQL** | Одна бесплатная БД на аккаунт, **срок жизни ограничен** (после срока — апгрейд или потеря данных без миграции) |
| **Blueprint** | Да |
| **HTTPS, логи из панели** | Да |

Цены и лимиты уточняйте на [render.com/free](https://render.com/free) — правила меняются.

---

## Ограничения free (важно для админов)

1. **Засыпание Web Service** — нет трафика ~15 мин → сервис останавливается. Первый запрос после паузы **долго «просыпается»** (десятки секунд и больше).
2. **Часы использования (instance hours)** — см. отдельный блок ниже.
3. **Бесплатная Postgres** — **не бессрочная**; см. блок «БД без оплаты» ниже.
4. **Диск контейнера** — **временный**; всё, что пишется только на локальный диск приложения, **теряется** при redeploy. Для постоянных файлов нужно внешнее хранилище (не входит в эту инструкцию).

**Вывод для админов:** free подходит для **демо, обучения, тестов**, а не для гарантированного 24/7 продакшена.

---

## Минимальные шаги запуска (free)

1. Репозиторий с **`Dockerfile`**, **`render.yaml`**, профиль **`prod`**.
2. **New + → Blueprint** (или Web Service вручную: Docker, тот же репо).
3. **PostgreSQL** — создать free инстанс, **скопировать External Database URL**.
4. У **Web Service** в **Environment**:
   - `SPRING_PROFILES_ACTIVE` = `prod`
   - `DATABASE_URL` = **полная** строка из панели БД (Copy).
5. **Deploy**; в логах — успешный старт без ошибок JDBC/Flyway.

Подробнее по кредам: `docs/RENDER_CREDENTIALS.md`.

## Что проверять администратору

| Симптом | Действие |
|---------|----------|
| Сайт долго открывается | Норма после простоя (cold start на free). |
| 502 / сервис «мёртвый» | Логи Deploy; возможно исчерпаны часы или сервис спит — открыть URL снова или подождать. |
| Ошибка БД при старте | `DATABASE_URL` целиком; при необходимости `DB_SSL_MODE=disable` или `require`. |
| БД пропала / истёк срок | По политике Render free Postgres — только **миграция на платный** или новая БД + восстановление из бэкапа (если успели выгрузить). |

## Чего на free нет (подробно)

### 1. Стабильный 24/7 без простоев и «вечно включённый» сайт

| На free | Что это значит для админов |
|---------|----------------------------|
| **Нет гарантии 24/7 в привычном смысле** | Web Service **сам засыпает**, если ~**15 минут** нет входящих запросов. Пока спит — для пользователя это не «всегда онлайн», а «по запросу». |
| **Нет мгновенного ответа после простоя** | Первый запрос после сна **поднимает** контейнер заново — часто **от ~30 секунд до минуты и больше** (cold start). Пользователи это воспринимают как «сайт лежит» или «очень тормозит». |
| **Нет SLA** | Free не позиционируется как продакшен: нет обязательств по аптайму, скорости пробуждения и т.п. |

**Итог:** бесплатный Web Service на Render — это **не** постоянно работающий сервер как на VPS с оплатой. Для демо/учебы ок; для «чтобы всегда открывалось за 1–2 секунды» — нужен **платный** план (сервис не засыпает по той же схеме).

---

### 2. «Вечная» БД без оплаты

| На free | Что это значит |
|---------|----------------|
| **Нет бессрочной бесплатной Postgres** | У бесплатной БД на Render **ограниченный срок жизни** с момента создания (в документации/changelog указывали порядка **30 дней**; раньше было дольше — правила меняются). |
| **После срока** | Нужно **перейти на платный** план БД **или** успеть **выгрузить данные** (дамп, миграция на другой хост). Иначе по правилам Render доступ может быть отключён, данные — удалены после **grace period**. |
| **Одна free БД** | Обычно **одна** бесплатная Postgres на аккаунт/команду — не «сколько угодно баз». |

**Итог:** «вечная БД только на free» **невозможна** по дизайну тарифа — это временный тестовый ресурс или старт с обязательным дальнейшим **платным** продлением/переносом.

---

### 3. Часы использования (instance hours)

По правилам Render для free workspace (актуальность — на [render.com/free](https://render.com/free)):

| Параметр | Обычно как устроено |
|----------|---------------------|
| **Лимит** | Порядка **750 бесплатных instance-часов в месяц** на **workspace** (аккаунт/команда), не «на каждый сервис отдельно бесконечно». |
| **Что такое «час»** | Время, пока **free web service** находится в **работающем** (не «замороженном») состоянии. Пока сервис **спит** после простоя, часы **не крутятся** так же, как у постоянно включённого инстанса — но каждый **запуск** и работа после запроса **расходуют** лимит. |
| **Сброс** | Лимит **обнуляется в начале календарного месяца**; **неиспользованные часы не переносятся**. |
| **Если лимит исчерпан** | **Все free web services** в workspace могут быть **приостановлены** до **начала следующего месяца** (пока часы снова не выделены). |
| **Несколько free сервисов** | Часы **общие**: два сервиса, каждый «включён» по 12 ч в сутки, съедают лимит быстрее, чем один. |

**Пример для оценки:** один free сервис, который **постоянно будят** (постоянный трафик), может приближаться к **24 × 31 ≈ 744** часам в месяц — то есть укладывается в **750** только если почти непрерывно крутится; если сервисы **часто спят**, суммарное время «в работе» меньше — лимит расходуется медленнее. Точные цифры и формулировки — только в официальной справке Render.

**Итог для админов:** на free есть **жёсткий потолок по часам работы** free web в месяц; при превышении — **простой до следующего месяца** или переход на **платный** план без этого лимита.

---

### 4. Прочее (кратко)

- **Нет** гарантированной производительности под нагрузкой (мало CPU/RAM на free).
- **Нет** постоянного диска у приложения (данные на диске контейнера не сохраняются между деплоями так же, как на платном проде с постоянным томом — уточняйте в доке Render).
